# Neural Weight Editing

A small experiment in repairing neural networks without retraining them.

I started this after reading [Weight-Space Programming](https://rikiyat.github.io/blog/weight-space-programming/). The question that interested me was whether an LLM could suggest a small edit to a model's weights after seeing a specific failure, and how we could tell if that edit was actually safe to use.

I'm starting with a simple 2D robot simulation and a small PyTorch policy network. I'll eventually compare three things: leaving the model alone, fine-tuning it on failure examples, and testing an LLM-proposed weight edit.

The important test is whether an edit fixes the original problem **without making other situations worse**.

## Current status

The first milestone is implemented. It contains a deterministic 7x7 gridworld, a supervised baseline policy, and separate ordinary and difficult evaluation layouts.

The policy is a small multilayer perceptron:

- 147 inputs: obstacle, robot and goal channels for the 7x7 grid
- one 32-unit tanh hidden layer
- 4 action outputs: up, down, left and right

It is trained by imitation learning from shortest paths generated by a breadth-first search expert. This keeps the initial experiment reproducible and avoids introducing reinforcement-learning instability before we study weight edits.

In one run, the baseline reached 62% of 50 ordinary held-out layouts and 3.3% of 30 deliberately difficult layouts. The difficult-layout result is expected to be poor at this stage; it gives us a separate failure set for later repair experiments. These are baseline results, not evidence that weight editing works.

## Running the first experiment

The project includes a local virtual environment with the required packages. From the repository root:

```bash
./.venv/bin/python -m pytest -q
./.venv/bin/python train_baseline.py
./.venv/bin/python evaluate_baseline.py
```

The training command writes `outputs/baseline.pt`. The evaluation command writes `outputs/baseline_evaluation.json`, including each layout, trajectory, success result and invalid-move count. These output files are ignored by Git.
